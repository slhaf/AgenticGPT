# Config API 与配置管理完善

## 任务与边界

为 Agent 增加独立的 config 工具集，提供配置说明、查询及修改能力；本次同时补齐 CLI/TUI 缺失的配置操作、说明文案及相关示例。用户已授权按本 planning 和响应示例开始完整实施，并要求所有入口进入现有公共 event frame。

用户要求用 planning 记录共识，不另建独立设计文档。调查结论见 findings.md，执行记录见 progress.md。本文中的共识是拟实施合同，不代表当前程序已经支持。

## 已确认共识

1. 工具维持 `config.manual`、`config.get`、`config.update` 三个，不额外拆分 list/reset/delete/validate 工具。
2. 配置寻址采用字符串路径段数组；配置值使用原生 JSON 类型。事件名和 MCP server ID 中的点属于单一路径段，不按点拆分。
3. 三端共用可扩展的配置描述目录：配置章节包含概述、关联语义和完整示例；条目包含真实路径、标题、简述、详细说明、类型/约束、默认规则、支持操作及示例。真实配置路径独立于手册章节和 TUI 页面，三端保留适合各自的呈现。
4. `manual` 使用 `section`、`query`、`detail`（summary/full）进行章节浏览、条目检索及文档式输出；不使用此前讨论的 toolset/path 双重筛选。无参数返回目录。详细条目保留必要的章节上下文与关联约束。
5. `get` 支持多路径/子树查询；区分未知路径、合法但不存在的条目、null 与脱敏结果。`explicit` 如保留，只表示当前文件中是否存在该项，不表示用户曾经显式设置的历史意图。以合并默认值后的持久配置为主，运行态不同时报告appliedValue与applyStatus。
6. 不使用 `revision`、`ifRevision` 或其他乐观并发前置条件。选择“按操作意图更新最新持久配置”，同一目标以后提交的操作为准。沿用现有配置写入锁串行提交，不新增并发管理框架。
7. `update` 包含 `changes` 和 `dryRun`。`set` 替换指定值/子树；`unset` 移除显式配置或 map 条目，不能删除必需项；只有支持集合语义的列表开放 `add/remove`，添加已存在项或移除不存在项无变化。有序列表整体编辑使用 set；第一版不支持数组下标寻址。
8. null 是配置值，与 unset 分开；例如 shell.initFile=null 表示禁用，unset 表示恢复默认。旧 CLI 的解析便利约定由 CLI adapter 映射，不能混入原生 JSON 更新层。
9. 一批操作按序组成完整候选，最终整体校验后一次保存。操作或校验失败不保存本次修改；写入阶段的错误必须区分尚未提交和 rename 后同步失败，不能声称所有错误都未改变文件。
10. dryRun 不保存本次修改；实写仍作用于届时最新配置，不保证预览和后续实写结果相同。
11. TUI 保留现有表单交互，提交实际编辑的字段/操作，不回写整个旧快照。集合增删保留 add/remove 意图，map 使用稳定 key 定位；最终校验失败保留草稿。
12. 本次覆盖 CLI/TUI 缺失配置项、实际编辑入口、提示/帮助、默认值说明、示例；不以仅补文字代替编辑能力，不要求每项新建专属命令或页面。
13. 共享层复用现有默认与业务校验；CLI 解析文本、TUI 产生原生值、API 接收原生值。TUI 布局、草稿和创建凭据文件等流程仍归 UI/既有事务所有者。
14. 实例启动契约与局部服务协调方案已获确认：mode/profile/agentId、Tunnel 身份/凭据/客户端启动参数保留显式重启边界；tunnel.hubReporting.detail 直接更新，enabled 由辅助 Hub 局部控制。其他服务以具体 owner 配合一个串行配置应用协调入口，不引入通用工厂或 DI 容器。当前实例及其故障恢复继续使用原启动契约，待重启值不能阻塞无关热更新。
15. config 工具集初始化/预设选中状态默认关闭，适用于 normal/room 等预设；已有显式 toolsets.enabled 不自动追加 config。未选中时按现有 Toolset 门禁不可调用。CLI/TUI 本地配置管理仍可使用，不因 config 工具集默认关闭而失去配置入口。
16. 配置 API 权限只针对整个 config.update 操作，采用一个独立的 allow/confirm 配置，不按字段增加权限矩阵。allow 仍需通过 Toolset/入口认证/校验；confirm 必须获得明确批准，确认渠道不可用时拒绝，拒绝/超时/取消也不写入，不回退 allow。整批变更一次判定/确认；manual/get 不增加写入确认。修改该权限自身也使用修改前的当前有效策略，不能由候选值自我放行。
17. config API 覆盖所有入口：Agent MCP stdio/Unix/HTTP、Hub HTTP、Hub Apps MCP 及其必要的 Hub-Agent wire/派发/响应映射。Hub 代理的是目标 Agent 的配置，不是 Hub 服务端配置；工具集与 update 策略由目标 Agent 统一执行，各入口保留自身认证与响应封套。
18. 独立更新权限字段采用 `config.updatePolicy`，默认 `confirm`；该命名及默认建议已获用户认可。

## 响应与失败合同（已确认）

用户已按给出的 get/update/dryRun/错误响应示例授权实施，“持久保存与运行态应用的返回合同”作为本次实现合同。敏感值沿用当前配置格式与脱敏边界，并补齐 API 参数/结果/预览/报告，不扩成字段权限矩阵。

响应合同：

- get 以合并默认值后的持久配置为主；当已应用值不同或组件未就绪时，带出实际已应用值/生效状态，避免将保存值误认为运行值。
- update 阻塞到保存与本次本地应用尝试结束；不无限等待外部系统恢复。分别报告保存结果、直接应用、待重启、连接中/应用失败等实际状态。
- 组件应用失败不回滚整份已保存配置；能保留旧实例则继续服务，否则明确报告该组件不可用。重试遵循各组件生命周期，不重放邮件发送/Secret写入等用户副作用，也不将失败组件错误投影为已应用。
- 校验失败仍整批不保存；组件应用不承诺跨所有组件的原子切换。

- 拟新增④⑤链路保障：批量关联修改原子校验及真实持久化；未知/含点路径与null/unset经过真实API；update严格确认不可用不写入；各入口Toolset关闭拒绝；结果公共events和敏感参数/结果脱敏。保护公开契约、配置完整性和授权边界，现有测试无config API，具备长期价值。

- 所有新增测试及smoke以独立HOME/XDG/TMP/D-Bus隔离；确保子进程退出后清理。
