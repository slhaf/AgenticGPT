## Source-level findings to carry into current diagnosis
1. **Agent dual routing, wire DTO as internal union.** `stdio_server::dispatch_with_lifecycle` routes direct resource operations and selected `HubCommand` trampolines through `local_service::dispatch`; Hub enters `local_service` directly. Both share WP2 `authorize` and resource implementations; there are not duplicate executors. A local-only operation should not need a Protocol Hub command to reuse an internal operation seam. Risk is change locality and projection drift, not a proven current behavior mismatch. Candidate: one shared operation family at a time, preserve ingress-specific hooks/error envelopes and migrate callers cleanly.
2. **Configuration lifetime/source-level discrepancy.** `jobs.rs::start_process_job_inner` clones config at line 1117 into `ManagedAuditContext` and admits/persists the Job; spawned `run_async_job` rereads live config at line 1301 for policy, CWD/preflight and confirmation. Source permits a reload interleaving to use different effective configs; not reproduced. `config::restart_required_fields`, main live-subset watcher and supervisor startup identity watcher have separate classifications. Choose/document a single snapshot rule and classification, then prove with deterministic reload scenario; preserve WP2 startup-resource refusal. Priority is resolving actual semantics before reorganizing files.
3. **Broad process-state access.** `state::AppState` bundles config/identity, Job/history, confirmation, MCP, Room, Skill, Browser and transport senders; `HubState` similarly bundles DB, agent/Room lease, Job cache, OAuth and ntfy. They work as composition roots; passing them widely hides domain dependencies and expands fixtures. Narrow contexts only at touched domains, preserve transition/lock owner; no blanket DI framework.
4. **Job/Skill owner coupling.** `jobs.rs` centralizes valuable Process/Skill/MCP Job terminalization but also holds effect-specific cancellation and SkillLeaseManager; `jobs -> skill_installs::package_sha256` couples core Job metadata to installation persistence while install manager uses Skill activation/lease. Extract narrowly only when caller migrations prove a real owner seam; do not unify SkillInstallStatus with JobState or Process kill with MCP cancel.
5. **Hub ingress duplication and reverse helper ownership.** HTTP `routes` and Apps MCP `mcp_server` independently project Job live/cache/freshness and construct operations; both converge on `agents::dispatch`/`runs`. `mcp_server::hub_info` calls `routes::build_hub_info_response`; room/notify/oauth/confirmation import route helpers. Consolidate neutral projection/info and only shared HTTP primitives, retaining different HTTP/MCP auth/error contracts. Apps MCP also has generated tools, manual dispatch, profile allowlist and effect annotations as separate inventories; require exact advertised/callable/profile parity.
6. **Protocol organization and command identity.** `protocol/src/lib.rs` is pure but holds every DTO/envelope and helper in one file; WP4-B is a justified internal ownership package, not a new crate. `HubCommand` serde names are separately mapped in Hub `runs::command_type` and Agent `operation::hub_command_name`; a pure wire-name function can eliminate those duplicate literals without conflating Apps names. Preserve exact serialized tags and persisted run identity.
7. **Same-root policy normalization.** `exec` and `file_ops` normalize configured roots separately; `policy::paths_match` also canonicalizes for config edits. Share only global configured-root normalization after a decision matrix. Room, Skill and Browser semantic paths have distinct trust roots and must remain separately validated.
8. **Independent Console state risk.** Android `AttentionListStateHolder` and `AttentionRuntimeCoordinator` each drive Room/scheduler/notifications; `AttentionScheduler.snooze(itemId,duration)` lacks enough payload and returns Degraded on Android, with UI workaround. Boot restore DAO query excludes overdue rows. Source-level lifecycle risk, not runtime-reproduced; assign Console local-only package with explicit overdue policy and OS scenario proof. Hub settings/Desktop/Web remain placeholders by decision, not core missing features.
9. **Release/contract inventories.** CI runs live parity but tag-triggered release packages binaries without that gate or a CI dependency; OpenAPI/Room gate and Apps descriptors repeat inventories. Document release version authorities and add a narrow release preflight/inventory parity package. Current parity gate and WP-R cutover remain valuable, not invalidated.
10. **Historical comments/suppressions.** Job history/Room write paths have stale dead-code attributes and a Phase 3 comment despite production use. Remove only demonstrably stale annotations when implementing a relevant seam; no blanket warning cleanup.

## Preserve and avoid
- Keep five crates, independent Console Gradle, pure apply-patch/Protocol, browser-host separate process, one Agent execution core, Hub control-plane/Room lease and Agent-owned content, layered durability and WP1/2/3/4-A/R fixes.
- Keep effect-specific lifecycles (Job Process/MCP, Skill install, Room maintenance, Browser lease, external tmux); no generic executor or universal repository/path/security/status framework.
- Do not infer Browser-host peer authentication from mode 0660 or try an owner-only redesign that breaks documented shared container topology. Production tunnel/GitHub/Android behavior and external Actions importer remain unverified.
- External/special surfaces are classified, not omitted: Console Android local Attention; Desktop/Web explicit placeholders; OpenAPI current vs agents-minimal historical; Python parity vs prediction evaluator; CI/release; UX demo and Chrome POC reference-only.
