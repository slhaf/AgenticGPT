# 任务：修复 Agentic Browser 运行时兼容性

## 目标
将已在 Room 上验证的新版 Browser 运行时及其配套依赖落实到 Agentic 项目，使项目的安装、发现和启动链路可用；确认 Browser Host 是否需要同步修改。

## 阶段
1. 核对项目分发、缓存、启动及 Host 协议，并实测旧版方式。已完成。
2. 保持官方运行时原样，在 Agentic 实现不需要 Codex 的自托管接法，更新过旧缓存，并使用远程构建器验证。已完成。
3. 审核变更并按项目要求提交；使用真实 Room 浏览器验证项目产物。已完成。
4. 调整远程 lint 的格式检查范围，与项目 CI 对齐并运行 Clippy。已完成。
5. 使用独立空缓存验证官方运行时自动安装和真实浏览器操作。已完成。
6. Room 的正式重装留待之后进行。

## 已知结果
- 旧版 26.908.70816 操作 Room 浏览器时跳转与关闭报 timeoutMs 错误。
- 来自官方签名包的 26.1027.51404 ARM64 Browser 文件与 Laptop 同版文件哈希一致；同包 codex 程序可供新版 app-server 使用，但最终方案不得要求它。
- 以隔离 HOME 运行的 Agentic 0.11.0 使用新版及配套程序，已在真实 Room 浏览器完成跳转、DOM、截图、点击和关闭；正式 Room 已通过部署级配置切换到该版本。

- 用户要求通过修改 browser-service 实现兼容，不能要求下载 Codex。直接实测：旧方式两处降级仍无法操作；在新版配置读取失败时使用空配置，并关闭后台联网后，无 Codex 环境中真实浏览器可完成导航、DOM、截图、点击和关闭，进程无错误日志。
