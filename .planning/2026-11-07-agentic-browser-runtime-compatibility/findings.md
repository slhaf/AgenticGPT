# 调查发现

- 项目 managed runtime 从官方签名仓库选择版本，只提取 cua_node 和 chrome；新版缺少 Codex 时直接读取配置会报错。
- 本次部署用系统服务环境变量提供同包 codex 程序，不能替代项目分发和启动修复。
- 需核对当前有效缓存、自动安装和包签名机制，避免项目升级后仍使用不完整的旧缓存。

- 用户明确要求最终行为不能要求下载 Codex。此前将完整 Codex 程序作为依赖的方案不再采用；需要沿用或实现原有无 Codex 的接法。
- 直接测试新版复用旧版 Full CDP 读取失败的降级，再忽略新增请求头读取：Chrome 可识别且可新建标签，但跳转和关闭仍因 requirements 读取失败。
- 新版 browser-service 临时修改为仅在 local-testing 模式下配置读取失败时返回空配置，并启用已有的 BROWSER_USE_DISABLE_AMBIENT_NETWORK，真实 Room 浏览器各项操作成功，stderr 无错误。其他模式保留原始报错行为。
- 稳定源当前提供 26.1103.32239，需要确认该版本能否使用 Agentic 一侧的无 Codex 接法。
- Laptop 和当前稳定包的 Chrome 插件均标记 Proprietary；不能把插件的修改版作为开源组件检入或分发。
- 在原版 26.1027.51404 Browser 文件不变的情况下，临时由 Agentic 一侧提供空配置，并禁用后台请求，在无 Codex 可执行文件的独立 HOME 中完成真实浏览器操作。该接法只用于已有的 local-testing 模式，不读取 Codex 配置或组织限制。
- 使用编译后的 Agentic 和真实 Room 浏览器，分别以 26.1027.51404 和经过官方签名及哈希验证的 26.1103.32239 完成打开、导航、读取、截图、点击和关闭；运行环境均未提供 Codex 程序。后一版本通过手动提取准备，未证明自动下载链路。
- 旧版 26.908.70816 缓存在禁用自动配置时被拒绝。实际自动下载在 Room 的网络条件下超过原有 5 分钟时限；源码已将大包下载时限改为 10 分钟，尚未完成实际下载重试。
